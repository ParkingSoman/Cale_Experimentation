## GPU attention fix and centerpiece decision (2026-10-15)
- A GPU that only reads prompts (gpu_layers=0) with flash attention on "auto" made decode 3x slower after long prompts (1.7 vs 4.6 tok/s at 7.6k tokens, HP MX150). Fixed in `cale/backends/llamalib.py` (attention on). `cale tune` measured only short prompts so it missed it. Lesson: a placement that wins on prompt reading can lose on answers; judge by the whole app run. When adding a placement/engine option, test decode after a long prompt (scratchpad `ctxdecode`: 87 / 1317 / 7617 tokens).
- Mac "no warning": `xattr -d com.apple.quarantine` on the download, not `prep_mac_demo.sh` (macOS 26 needs a manual confirm). `sudo` cannot run through the `!` prefix: use the Terminal app.
- Centerpiece (late 2026-10-15): ONE app (Quick Notes) with absolute-vs-relative A/B per computer (`scripts/ab_absolute_relative.py`) plus the one-install claim (later narrowed: show only relative). Other four apps = funding case: size ladder (100% to 48%) only ~1.7x wide vs 6.5x Mac/old-HP gap, so a Matryoshka model with many more slices is needed. A/B found a second bug: short-prompt first-token prediction at small sizes on a GPU that reads prompts (fixed with `pre_curve_small`). Pitch page honest: never claim "same feel everywhere"; claim goals are met where the ladder allows and misses are reported. HP Windows and Linux rows are ONE laptop.
