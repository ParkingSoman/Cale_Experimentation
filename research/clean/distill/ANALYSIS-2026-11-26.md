### The main error

The concept says the tree changes everything in ONE operation (`THEORY.md` line 31: "past folds … kept fine readers that still wanted the fine message. The tree changes both in one operation."). FANOUT round 1 then split it into parts P0-P6. Since then, no build made every part coarse together with the concept's own write. Each test put coarse parts into a network whose other parts were still fine, or still repaired by a fit.

| Test | What was coarse | What stayed fine or fitted | Result | What we concluded |
|---|---|---|---|---|
| round 2 OR-merge (`rules/r2_p1p3_merge.py`) | MLP of every block: summed read, union gate | heads and stream full; the write was a ridge fit (P4 fold), not the branch's summed write | 50.5% vs 64.0% (quick, 85%) | "merge is the wrong form" |
| round 3 read tilts (`rules/r3_tree_*.py`) | kept MLP reads tilted .1 toward a partner | everything else; write = fit | tie or loss | "dead end" |
| L2 gate (tonight, `rules/l2_gate_r18_*.py`) | kept gates opened to the union rate | fine reads, pruned writes, fitted folds | 32.4% vs 32.6% (full 1,000) | almost "gate does not help" |
| L1 stream (`rules/l1_stream.py`) | stream from kept nodes | pruned (fine) nodes | no free width | "stream needs the full span" |

Each result is what the concept PREDICTS when one part is coarse and the others are fine: a broad gate on a fine read fires in the wrong places, and a narrow stream cannot hold fine writes. One exception keeps its weight: the summed read also lost against a trained answer key (THEORY section 5, N11-weights). So the summed read is not the default.
